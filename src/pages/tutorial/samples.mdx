<L to="/tutorial/sounds">Picking Sounds</L> covered how to *load* and *select* samples. This chapter
is about what you can do to one once it is playing, and you do all of it by typing: each step asks
for one change, you press ctrl+enter, and you listen.

Several exercises start with a `samples('github:…')` line. That line only registers the names — the
audio itself downloads the first time you ask for it, so the first hit of a new sample is often
silent. Play it twice. (Chaining `._scope()` on any pattern draws the waveform, which is a quick way
to see whether anything arrived at all.)

## Playback rate

`speed` is a turntable: it changes pitch and duration together. Double the speed and you get the
octave above, in half the time. Negative values run the tape backwards.

<Exercise id="samples/speed" title="Spin it faster, then backwards"
  goal="Pitch a kick up and down with `speed`, then pattern it, then reverse it."
  start={`s("bd bd bd bd")`}
  target={`s("bd bd bd bd")
  .speed("1 2 -1 -2")`}>
  <Step check={{ includes: '.speed(', has: { speed: 2 } }}
        solution={`s("bd bd bd bd")
  .speed(2)`}>
    Add `.speed(2)` on a new line. An octave up and half as long — the kick turns into a tom hit.
  </Step>
  <Step check={{ has: { speed: 0.5 } }}
        hints={['Halving the rate drops it an octave.']}
        solution={`s("bd bd bd bd")
  .speed(.5)`}>
    Change the `2` to `.5`. An octave down, twice as long, and suddenly it is a sub drop.
  </Step>
  <Step check={{ match: { keys: ['speed'] } }}
        target={`s("bd bd bd bd")
  .speed("1 2 4 8")`}
        hints={['`speed` takes mini-notation like every other argument.']}
        solution={`s("bd bd bd bd")
  .speed("1 2 4 8")`}>
    Change it to `.speed("1 2 4 8")`: one value per kick, climbing four octaves across the bar.
  </Step>
  <Step check={{ includes: '-1', match: { keys: ['s', 'speed'] } }}
        hints={['A minus sign in front of the number plays the file from the end.']}
        solution={`s("bd bd bd bd")
  .speed("1 2 -1 -2")`}>
    Change the last two values to `-1 -2`: `.speed("1 2 -1 -2")`. The last two play backwards. On
    a kick that is a suck-in; on a crash it is the classic reverse-cymbal lead-in.
  </Step>
</Exercise>

<Exercise id="samples/speed-challenge" title="Challenge: every other one backwards"
  goal="Eight kicks in the bar. The odd ones normal, the even ones backwards at double speed."
  start={`s("bd*8")`}
  target={`s("bd*8").speed("[1 -2]*4")`}
  check={{ match: { keys: ['s', 'speed'] } }}
  hints={[
    'The speed pattern needs eight values, but only two of them are different.',
    '`[a b]*4` repeats a pair of values four times across the bar.',
    'Backwards at double speed is one number, not two.',
  ]} />

`stretch` does the other half of the job: it moves the pitch and leaves the duration alone, using a
phase vocoder.

<Exercise id="samples/stretch" title="Pitch without time"
  goal="Shift a rhodes chord up and down without its length changing."
  start={`samples({ rhodes: 'https://cdn.freesound.org/previews/132/132051_316502-lq.mp3' })
s("rhodes").speed("<1 2>")`}
  target={`samples({ rhodes: 'https://cdn.freesound.org/previews/132/132051_316502-lq.mp3' })
s("rhodes").stretch("<2 1 0 -2>")`}>
  <Step check={{ excludes: '.speed(', has: { stretch: 2 } }}
        hints={['Same shape of call, different name.']}
        solution={`samples({ rhodes: 'https://cdn.freesound.org/previews/132/132051_316502-lq.mp3' })
s("rhodes").stretch(2)`}>
    Listen to the start first: the second pass is shorter as well as higher. Now replace
    `.speed("<1 2>")` with `.stretch(2)`. Higher, and exactly as long as before.
  </Step>
  <Step check={{ has: { stretch: -2 } }}
        solution={`samples({ rhodes: 'https://cdn.freesound.org/previews/132/132051_316502-lq.mp3' })
s("rhodes").stretch(-2)`}>
    Change it to `.stretch(-2)`: down instead of up, still the same length. This is what a DAW
    calls transposition on a warped clip.
  </Step>
  <Step check={{ cycles: 4, match: { keys: ['s', 'stretch'] } }}
        solution={`samples({ rhodes: 'https://cdn.freesound.org/previews/132/132051_316502-lq.mp3' })
s("rhodes").stretch("<2 1 0 -2>")`}>
    Change it to `.stretch("<2 1 0 -2>")`. Up, a little up, unchanged, down — and listen for the
    smearing on the extreme values. A phase vocoder is not free.
  </Step>
</Exercise>

<Box>
`speed` is cheap and sounds like a sampler. `stretch` is expensive and sounds like a studio. For
drums, `speed` is usually more musical; for melodic material, `stretch` keeps your timing intact.
</Box>

## Fitting a sample to the grid

A two-bar break recorded at 174 bpm will not line up with your pattern. Two tools fix that, and
both of them work **by setting `speed`** — so the pitch moves with the tempo, exactly like a
turntable. `stretch` is the only one that does not.

<Exercise id="samples/fit" title="Lock a break to the cycle"
  goal="Make a whole break fill its event, at three different lengths, two different ways."
  start={`samples('github:yaxu/clean-breaks')
s("amen/2")`}
  target={`samples('github:yaxu/clean-breaks')
s("amen")
  .loopAt(4)`}>
  <Step check={{ includes: '.fit()', has: { unit: 'c' } }}
        hints={['It takes no arguments: the event length is the argument.']}
        solution={`samples('github:yaxu/clean-breaks')
s("amen/2")
  .fit()`}>
    The break is playing at its recorded speed and drifting out of time. Add `.fit()` on a new
    line: the file is resampled to fill its event exactly, and `amen/2` makes that event two
    cycles long.
  </Step>
  <Step check={{ fn: "(h) => h.length > 0 && h.every((e) => Math.abs(e.value.speed - 1) < 1e-6) || 'Expected the break fitted to one cycle (speed 1).'" }}
        hints={['The `/2` is what makes the event two cycles long.']}
        solution={`samples('github:yaxu/clean-breaks')
s("amen")
  .fit()`}>
    Change `s("amen/2")` to `s("amen")`. The event is one cycle now, so `fit` plays the file twice
    as fast to fill it: it jumps up an octave on the way.
  </Step>
  <Step check={{ fn: "(h) => h.every((e) => Math.abs(e.value.speed - 0.25) < 1e-6) || 'Expected the break stretched over four cycles (speed 0.25).'" }}
        hints={['`x/n` spreads one event over n cycles, and `fit` follows whatever event it lands on.']}
        solution={`samples('github:yaxu/clean-breaks')
s("amen/4")
  .fit()`}>
    Change `s("amen")` to `s("amen/4")`. The event is now four cycles long, so `fit` slows the file
    down to match — and it drops two octaves on the way. `fit` is a turntable, not a time-stretcher.
  </Step>
  <Step check={{ includes: '.loopAt(', excludes: '.fit()', has: { unit: 'c' } }}
        hints={['`loopAt` takes the number of cycles you want the file to last.']}
        solution={`samples('github:yaxu/clean-breaks')
s("amen/4")
  .loopAt(4)`}>
    Say the same thing the other way round: change `.fit()` to `.loopAt(4)`. Now wait. The break
    plays for four cycles and then goes quiet for twelve, because `loopAt` slows the *pattern* as
    well as the playback, and the `/4` was already slowing it.
  </Step>
  <Step check={{ cycles: 8, match: { keys: ['s', 'speed', 'unit'] } }}
        target={`samples('github:yaxu/clean-breaks')
s("amen")
  .loopAt(4)`}
        hints={['`loopAt` already makes the event four cycles long.']}
        solution={`samples('github:yaxu/clean-breaks')
s("amen")
  .loopAt(4)`}>
    Change `s("amen/4")` back to `s("amen")`. The file spans four cycles and comes straight back
    round. Same pitch drop as `amen/4` with `fit`, because it is the same mechanism.
  </Step>
</Exercise>

<Exercise id="samples/fit-challenge" title="Challenge: lock it to the kick"
  goal="Two lanes: the break spread over four bars and fitted to them, plus a `bd` on every beat so you can hear it lock."
  start={`samples('github:yaxu/clean-breaks')

    'Only one of the two lanes needs anything added.',
    'The break already lasts four cycles; it just is not playing at the right rate.',
  ]} />

## Trimming: begin and end

`begin` and `end` are fractions of the file, from 0 to 1. They pick the part that plays.

<Exercise id="samples/trim" title="Cut the front and the back off"
  goal="Shorten a sample from the end, then skip into it from the front."
  start={`samples({ rave: 'rave/AREUREADY.wav' }, 'github:tidalcycles/dirt-samples')
s("rave*2")`}
  target={`samples({ rave: 'rave/AREUREADY.wav' }, 'github:tidalcycles/dirt-samples')
s("rave*2").begin("<0 .25 .5 .75>")`}>
  <Step check={{ includes: '.end(', has: { end: [0.1, 0.4] } }}
        hints={['`.25` means a quarter of the way through the file, not a quarter of a second.']}
        solution={`samples({ rave: 'rave/AREUREADY.wav' }, 'github:tidalcycles/dirt-samples')
s("rave*2").end(.25)`}>
    Add `.end(.25)`: only the first quarter of the file plays. A vocal sample becomes a stab.
  </Step>
  <Step check={{ cycles: 4, match: { keys: ['end'] } }}
        target={`samples({ rave: 'rave/AREUREADY.wav' }, 'github:tidalcycles/dirt-samples')
s("rave*2").end("<.25 .5 .75 1>")`}
        solution={`samples({ rave: 'rave/AREUREADY.wav' }, 'github:tidalcycles/dirt-samples')
s("rave*2").end("<.25 .5 .75 1>")`}>
    Change it to `.end("<.25 .5 .75 1>")`: the phrase gets one quarter longer each bar. Note that
    nothing moves in time — trimming the end never changes when the next event starts.
  </Step>
  <Step check={{ includes: '.begin(', excludes: '.end(', has: { begin: [0.3, 0.7] } }}
        solution={`samples({ rave: 'rave/AREUREADY.wav' }, 'github:tidalcycles/dirt-samples')
s("rave*2").begin(.5)`}>
    Replace `.end(...)` with `.begin(.5)`: playback starts halfway into the file. This is how you
    find the syllable you actually want.
  </Step>
  <Step check={{ cycles: 4, match: { keys: ['s', 'begin'] } }}
        solution={`samples({ rave: 'rave/AREUREADY.wav' }, 'github:tidalcycles/dirt-samples')
s("rave*2").begin("<0 .25 .5 .75>")`}>
    Change it to `.begin("<0 .25 .5 .75>")` and walk through the file a quarter at a time.
  </Step>
</Exercise>

  start={`s("oh*8")`}
  target={`s("oh*8").begin(.25).end(.75)`}

  ]} />

## chop — grains

`chop(n)` cuts every event into `n` consecutive pieces and plays them in order. On its own you hear
nothing new; the point is what you do to the pieces afterwards.

<Exercise id="samples/chop" title="Mangle a break"
  goal="Cut a break into grains, reverse their order, then stutter and reverse them at random."
  start={`samples('github:yaxu/clean-breaks')
s("amen/2")
  .fit()`}
  target={`samples('github:yaxu/clean-breaks')
s("amen/2")
  .fit()
  .chop(8)
  .rev()
  .cut(1)
  .sometimesBy(.5, ply("2"))
  .sometimesBy(.25, mul(speed("-1")))`}>
  <Step check={{ includes: '.chop(', cycles: 2, events: 8 }}
        hints={['One argument: how many pieces.']}
        solution={`samples('github:yaxu/clean-breaks')
s("amen/2")
  .fit()
  .chop(8)`}>
    Add `.chop(8)` on a new line. It sounds identical — eight pieces of the same file, played back
    to back in the right order, is just the file.
  </Step>
  <Step check={{ includes: '.rev(', cycles: 2, match: { keys: ['begin', 'end'] } }}
        target={`samples('github:yaxu/clean-breaks')
s("amen/2")
  .fit()
  .chop(8)
  .rev()`}
        hints={['`rev` reverses the order of the events, not the audio inside them.']}
        solution={`samples('github:yaxu/clean-breaks')
s("amen/2")
  .fit()
  .chop(8)
  .rev()`}>
    `rev()` plays the events of each cycle in reverse order. Add `.rev()` on a new line. Now the
    grains play last-to-first: the same drums, in a new order, each one still forwards. That is
    what `chop` is for.
  </Step>
  <Step check={{ includes: '.cut(', has: { cut: 1 } }}
        solution={`samples('github:yaxu/clean-breaks')
s("amen/2")
  .fit()
  .chop(8)
  .rev()
  .cut(1)`}>
    Add `.cut(1)`. Any two events in the same cut group cannot overlap — a new one stops the
    previous. It should get tighter and less washy immediately.
  </Step>
  <Step check={{ includes: '.ply(', cycles: 2, events: 16 }}
        hints={['`ply(n)` repeats each event n times inside its own slot.']}
        solution={`samples('github:yaxu/clean-breaks')
s("amen/2")
  .fit()
  .chop(8)
  .rev()
  .cut(1)
  .ply(2)`}>
    `ply(n)` plays every event n times, squeezed into the slot the one event had. Add `.ply(2)`:
    sixteen grains where there were eight, every one of them doubled.
  </Step>
  <Step check={{ includes: 'sometimesBy(', cycles: 2, events: [9, 24] }}
        hints={['`sometimesBy(p, f)` applies `f` to each event with probability `p`.',
                'The `ply` goes inside it, as the function; in that position it is written `ply("2")`, with no dot.']}
        solution={`samples('github:yaxu/clean-breaks')
s("amen/2")
  .fit()
  .chop(8)
  .rev()
  .cut(1)
  .sometimesBy(.5, ply("2"))`}>
    `sometimesBy(p, f)` applies a function to each event with probability `p`. Change `.ply(2)` to
    `.sometimesBy(.5, ply("2"))`. Half the grains double up: the stutter that jungle is built on.
  </Step>
  <Step check={{ includes: 'mul(speed(', cycles: 2, events: [9, 24] }}
        hints={['`mul` multiplies a control that is already there, instead of replacing it — `fit` has already set `speed`.']}
        solution={`samples('github:yaxu/clean-breaks')
s("amen/2")
  .fit()
  .chop(8)
  .rev()
  .cut(1)
  .sometimesBy(.5, ply("2"))
  .sometimesBy(.25, mul(speed("-1")))`}>
    Add `.sometimesBy(.25, mul(speed("-1")))`. A quarter of the grains now play backwards, and
    because it *multiplies*, the speed `fit` computed is preserved.
  </Step>
</Exercise>

<Box>
`cut(1)` puts every event in cut group 1, meaning each new one **stops** the previous. Without it,
overlapping chops pile up into mush. Any time you chop, reach for `cut`. Different numbers are
different groups, so hats can choke hats without touching the bass.
</Box>

<Exercise id="samples/chop-challenge" title="Challenge: grains in reverse"
  goal="A rhodes chord stretched over two bars, cut into four grains that play in reverse order."
  start={`samples({ rhodes: 'https://cdn.freesound.org/previews/132/132051_316502-lq.mp3' })
s("rhodes").loopAt(2)`}
  target={`samples({ rhodes: 'https://cdn.freesound.org/previews/132/132051_316502-lq.mp3' })
s("rhodes").chop(4).rev().loopAt(2)`}
  check={{ includes: ['.chop(', '.rev('], cycles: 2, match: { keys: ['s', 'begin', 'end', 'speed'] } }}
  hints={[
    'Two functions, chained before the one that is already there.',
    'One cuts the file into pieces, the other flips the order they come in.',
  ]} />

## slice and splice — choosing the order

`chop` plays the pieces in order. `slice(n, pattern)` lets you say which piece plays when.

<Exercise id="samples/slice" title="Re-sequence a break"
  goal="Number the pieces of a break, play them in any order, then let `splice` fix the timing."
  start={`samples('github:yaxu/clean-breaks')
s("amen")
  .fit()`}
  target={`samples('github:yaxu/clean-breaks')
s("amen")
  .splice(8, "7 6 5 4 3 2 1 0")
  .cut(1)`}>
  <Step check={{ includes: '.slice(', events: 8 }}
        hints={['Two arguments: how many pieces the file has, and which of them to play.']}
        solution={`samples('github:yaxu/clean-breaks')
s("amen")
  .fit()
  .slice(8, "0 1 2 3 4 5 6 7")`}>
    Add `.slice(8, "0 1 2 3 4 5 6 7")` on a new line. Identical to `chop(8)` so far — but now every
    piece has a number you can move around. Note where the rhythm comes from: with `slice` it is
    the index pattern, not the event you chained onto.
  </Step>
  <Step check={{ match: { keys: ['begin'] } }}
        target={`samples('github:yaxu/clean-breaks')
s("amen")
  .fit()
  .slice(8, "7 6 5 4 3 2 1 0")`}
        hints={['The second argument is an ordinary mini-notation pattern of indices.']}
        solution={`samples('github:yaxu/clean-breaks')
s("amen")
  .fit()
  .slice(8, "7 6 5 4 3 2 1 0")`}>
    Reverse the order by hand: `.slice(8, "7 6 5 4 3 2 1 0")`. Try `"0 0 4 0 2 [4 5] 6 7"` too —
    any pattern of numbers works, including `*`, `< >` and rests. Listen to the ones that repeat:
    each piece still plays at its own speed, so it does not fill its slot.
  </Step>
  <Step check={{ includes: '.splice(', excludes: '.slice(' }}
        hints={['One letter more than `slice`.']}
        solution={`samples('github:yaxu/clean-breaks')
s("amen")
  .fit()
  .splice(8, "7 6 5 4 3 2 1 0")`}>
    Change `slice` to `splice`. `splice` is `slice` plus an automatic `speed` for each piece, so
    every piece fills its slot exactly however you re-order or repeat them.
  </Step>
  <Step check={{ excludes: '.fit()', match: { keys: ['s', 'begin', 'end', 'speed'] } }}
        target={`samples('github:yaxu/clean-breaks')
s("amen")
  .splice(8, "7 6 5 4 3 2 1 0")`}
        hints={['One deletion.']}
        solution={`samples('github:yaxu/clean-breaks')
s("amen")
  .splice(8, "7 6 5 4 3 2 1 0")`}>
    `splice` already sets the speed, so `fit` has nothing left to do: delete that line. Try
    `"<0 1 2 3 4*2 5 6 [6 7]>*2"` as the index pattern — however you subdivide, `splice` keeps
    every piece in time.
  </Step>
  <Step check={{ has: { cut: 1 }, match: { keys: ['s', 'begin', 'end', 'speed', 'cut'] } }}
        solution={`samples('github:yaxu/clean-breaks')
s("amen")
  .splice(8, "7 6 5 4 3 2 1 0")
  .cut(1)`}>
    Add `.cut(1)` again, for the same reason as before: slices that overlap sound like a smear.
  </Step>
</Exercise>

The slice points do not have to be even. Pass an array instead of a count —
`.slice([0, .25, .5, .75], "0 1 1 <2 3>")` — and you can mark where the interesting moments actually
are in the file.

<Exercise id="samples/slice-challenge" title="Challenge: first half, second half"
  goal="Eight slices of the break: bar 1 plays 0 1 2 3, bar 2 plays 4 5 6 7, in time, each slice cutting the last."
  start={`samples('github:yaxu/clean-breaks')
s("amen")`}
  target={`samples('github:yaxu/clean-breaks')
s("amen").splice(8, "<[0 1 2 3] [4 5 6 7]>").cut(1)`}

    '“In time” rules out one of the two functions.',

## striate — interlacing

Where `chop` keeps each sample's pieces together, `striate(n)` plays the **first** piece of every
sample, then the second of every sample, and so on. It braids a sequence of sounds into each other.

<Exercise id="samples/striate" title="Braid three samples"
  goal="Hear the difference between chopping three samples and interlacing them."
  start={`s("numbers:0 numbers:1 numbers:2")`}
  target={`s("numbers:0 numbers:1 numbers:2").striate(6).slow(3)`}>
  <Step check={{ includes: '.chop(', events: 12 }}
        solution={`s("numbers:0 numbers:1 numbers:2").chop(4)`}>
    Add `.chop(4)`: twelve events, but you still hear three separate words, each stuttered.
  </Step>
  <Step check={{ includes: '.striate(', excludes: '.chop(', match: { keys: ['s', 'n', 'begin', 'end'] } }}
        target={`s("numbers:0 numbers:1 numbers:2").striate(4)`}
        hints={['Same argument, different function name.']}
        solution={`s("numbers:0 numbers:1 numbers:2").striate(4)`}>
    Change `chop` to `striate`. The same twelve pieces, reordered: first quarter of each word,
    then second quarter of each word. One braided texture instead of three stutters.
  </Step>
  <Step check={{ events: 18 }}
        solution={`s("numbers:0 numbers:1 numbers:2").striate(6)`}>
    Change it to `.striate(6)`: finer pieces, so the three sources blur further into each other.
  </Step>
  <Step check={{ includes: '.slow(', cycles: 3, match: { keys: ['s', 'n', 'begin', 'end'] } }}
        hints={['Eighteen events in one cycle is a blur; give them three.']}
        solution={`s("numbers:0 numbers:1 numbers:2").striate(6).slow(3)`}>
    Add `.slow(3)` so you can actually hear the braid.
  </Step>
</Exercise>

gives you three stuttered words, `striate` gives you one texture made of all three.
</Box>

## scrub — the tape head

`scrub` takes positions in the file and plays from each of them, so you can drag the playhead around
in rhythm. A colon adds a playback speed to a position.

<Exercise id="samples/scrub" title="Drag the playhead"
  goal="Jump around inside a pad in a fixed rhythm, then speed up one of the jumps."
  start={`samples('github:switchangel/pad')
s("swpad:0")`}
  target={`samples('github:switchangel/pad')
s("swpad:0")
  .scrub("{ 0!3 .25 .5!2 <0.75:1.5>@2 }%8")`}>
  <Step check={{ includes: '.scrub(', events: 8 }}
        hints={['The positions are fractions of the file, like `begin`.']}
        solution={`samples('github:switchangel/pad')
s("swpad:0")
  .scrub("{ 0 .25 .5 .75 }%8")`}>
    Add `.scrub("{ 0 .25 .5 .75 }%8")` on a new line. Eight steps per cycle walking through four
    positions: the pad is being played by a very steady hand.
  </Step>
  <Step check={{ events: 7, match: { keys: ['begin'] } }}
        target={`samples('github:switchangel/pad')
s("swpad:0")
  .scrub("{ 0!3 .25 .5!2 .75@2 }%8")`}
        hints={['`!` repeats a position as separate steps, `@` makes one step longer.']}
        solution={`samples('github:switchangel/pad')
s("swpad:0")
  .scrub("{ 0!3 .25 .5!2 .75@2 }%8")`}>
    Give it a rhythm: change `0` to `0!3`, `.5` to `.5!2` and `.75` to `.75@2`. Still eight
    steps, but they are no longer one event each — the `@2` holds the playhead in one place for two
    of them.
  </Step>
  <Step check={{ includes: ':1.5', fn: "(h) => h.some((e) => e.value.speed === 1.5) || 'One position should carry a speed of 1.5.'" }}

## Looping

`loop(1)` makes a sample repeat for as long as its event lasts. `loopBegin` and `loopEnd` set the
loop points, as fractions of the file.

<Exercise id="samples/looping" title="Loop a piece of a pad"
  goal="Loop a pad, then narrow the loop until the repeats turn into a pitch."
  start={`samples('github:switchangel/pad')
s("swpad:0")`}
  target={`samples('github:switchangel/pad')
s("swpad:0")
  .loop(1)
  .loopEnd(.26)
  .loopBegin(.25)`}>
  <Step check={{ includes: '.loop(', has: { loop: 1 } }}
        solution={`samples('github:switchangel/pad')
s("swpad:0")
  .loop(1)`}>
    Add `.loop(1)` on a new line. The pad now restarts as often as it needs to fill the cycle
    instead of decaying away.
  </Step>
  <Step check={{ has: { loopEnd: [0.3, 0.7] } }}
        solution={`samples('github:switchangel/pad')
s("swpad:0")
  .loop(1)
  .loopEnd(.5)`}>
    Add `.loopEnd(.5)`: only the first half of the file is in the loop, so it comes round twice as
    often.
  </Step>
  <Step check={{ includes: '.loopBegin(', has: { loopBegin: [0.1, 0.4] } }}
        hints={['Playback still starts at the top of the file; this only moves the point it jumps back to.']}
        solution={`samples('github:switchangel/pad')
s("swpad:0")
  .loop(1)
  .loopEnd(.5)
  .loopBegin(.25)`}>
    Add `.loopBegin(.25)`. The loop is now the quarter of the file between .25 and .5.
  </Step>
  <Step check={{ has: { loopEnd: [0.25, 0.3] }, match: { keys: ['s', 'loop', 'loopBegin', 'loopEnd'] } }}
        hints={['Move the end almost onto the beginning.']}
        solution={`samples('github:switchangel/pad')
s("swpad:0")
  .loop(1)
  .loopEnd(.26)
  .loopBegin(.25)`}>
    Change the end to `.loopEnd(.26)`: a 1% window. The loop now repeats hundreds of times a
    second, and you hear a pitch instead of a rhythm. Add a `note("<c3 eb3>")` and it plays like a
    synth — which is exactly how the `wt_*` wavetables in
    <L to="/tutorial/synths">Synths</L> work.
  </Step>
</Exercise>

## Running through a sample bank

When one sound name holds many similar recordings, `n` picks between them and `run(n)` sweeps
through the lot.

<Exercise id="samples/run-bank" title="Sweep a bank"
  goal="Play eight different tabla recordings in a row, then move the phrase onto the beat."
  start={`samples('bubo:fox')
s("ftabla*8")`}
  target={`samples('bubo:fox')
s("ftabla*8")
  .n(run(8))
  .early(2/8)
  .sometimes(mul(speed("1.5")))`}>
  <Step check={{ includes: 'run(', match: { keys: ['n', 's'] } }}
        target={`samples('bubo:fox')
s("ftabla*8")
  .n(run(8))`}
        hints={['`run(8)` is the pattern `0 1 2 3 4 5 6 7`. The rhythm still comes from `ftabla*8` on the left.']}
        solution={`samples('bubo:fox')
s("ftabla*8")
  .n(run(8))`}>
    `run(n)` is the pattern `0 1 … n-1`, one step each. Add `.n(run(8))` on a new line: still
    eight events, but each one is a different recording from the bank.
  </Step>
  <Step check={{ includes: '.early(', match: { keys: ['n'] } }}
        target={`samples('bubo:fox')
s("ftabla*8")
  .n(run(8))
  .early(2/8)`}
        hints={['`early(x)` pulls the whole pattern x cycles earlier; an eighth of a cycle is `1/8`.']}
        solution={`samples('bubo:fox')
s("ftabla*8")
  .n(run(8))
  .early(2/8)`}>
    The musical phrase in a bank rarely starts at index 0. Add `.early(2/8)` to rotate the whole
    run two slots earlier, so it starts on sample 2.
  </Step>
  <Step check={{ includes: '.speed(', events: 8, has: { speed: 1.5 } }}
        solution={`samples('bubo:fox')
s("ftabla*8")
  .n(run(8))
  .early(2/8)
  .speed(1.5)`}>
    Add `.speed(1.5)`: every hit jumps up a fifth.
  </Step>
  <Step check={{ includes: 'sometimes(', events: 8 }}
        hints={['`sometimes` is `sometimesBy(.5, …)`, and `mul` multiplies a control instead of setting it.']}
        solution={`samples('bubo:fox')
s("ftabla*8")
  .n(run(8))
  .early(2/8)
  .sometimes(mul(speed("1.5")))`}>
    `sometimes(f)` is `sometimesBy(.5, f)`. Change `.speed(1.5)` to
    `.sometimes(mul(speed("1.5")))`: now only half the hits jump up a fifth. A bank plus a little
    randomness is a whole percussion track.
  </Step>
</Exercise>

<QA q="chop, slice, splice, striate — which one?">
`chop` when you want to mangle a single sound into grains. `slice` when you want to re-sequence a
break and you will handle the timing yourself. `splice` when you want to re-sequence a break and
have it stay in time automatically — this is the one you want most of the time. `striate` when you
want to blend several different samples into one texture.
</QA>

## Recap

| Function | Purpose |
| --- | --- |
| `speed` | playback rate (pitch + time), negative = backwards |
| `stretch` | pitch without time |
| `fit` | resample so the file fills its event (pitch moves) |
| `loopAt(n)` | resample so the file spans n cycles (pitch moves) |
| `begin` `end` | trim the file |
| `chop(n)` | cut into n consecutive grains |
| `slice(n, pat)` | play named pieces |
| `splice(n, pat)` | slice, with speed corrected |
| `striate(n)` | interlace pieces of several samples |
| `scrub` | play from arbitrary positions, `position:speed` |
| `loop` `loopBegin` `loopEnd` | looped playback |
| `cut(n)` | cut group — a new event stops the previous |
| `n` + `run(n)` | step through a bank of recordings |
