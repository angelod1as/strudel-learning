Up to now most functions have set a parameter. These do something stranger: they take the whole
pattern as input and transform its **structure**. This is where Strudel stops being a sequencer.

None of them can be read off the page. You have to hear them, so every one below is something you
type into a running pattern and listen to.

## Reverse

<Exercise id="pattern-functions/rev" title="Backwards, and back again"
  goal="Hear the difference between reversing inside a cycle and reversing the cycles themselves."
  start={`n("<[0 2 4 7] [9 11 12 14]>").scale("C:minor").s("piano")`}
  target={`n("<[0 2 4 7] [9 11 12 14]>").scale("C:minor").s("piano").palindrome()`}>
  <Step check={{ includes: '.rev()', cycles: 2, match: { keys: ['note'] } }}
        target={`n("<[0 2 4 7] [9 11 12 14]>").scale("C:minor").s("piano").rev()`}
        hints={['It chains on the end, like any other function.']}
        solution={`n("<[0 2 4 7] [9 11 12 14]>").scale("C:minor").s("piano").rev()`}>
    Two bars: a low group, then a high one. Add `.rev()` to the end. Each bar is now played
    backwards — but the low group is still first. `rev` works *inside* a cycle.
  </Step>
  <Step check={{ includes: '.revv()', cycles: 2, match: { keys: ['note'] } }}
        target={`n("<[0 2 4 7] [9 11 12 14]>").scale("C:minor").s("piano").revv()`}
        hints={['One more `v`.']}
        solution={`n("<[0 2 4 7] [9 11 12 14]>").scale("C:minor").s("piano").revv()`}>
    Change `.rev()` to `.revv()`. Now the **bars** swap too: the high group comes first.
  </Step>
  <Step check={{ includes: '.palindrome()', cycles: 2, match: { keys: ['note'] } }}
        target={`n("<[0 2 4 7] [9 11 12 14]>").scale("C:minor").s("piano").palindrome()`}
        hints={['`palindrome` is `rev` applied to every other cycle.']}
        solution={`n("<[0 2 4 7] [9 11 12 14]>").scale("C:minor").s("piano").palindrome()`}>
    Change `.revv()` to `.palindrome()`. Bar 1 forwards, bar 2 backwards.
  </Step>
</Exercise>

<Box>
`rev` reverses each cycle on its own. `revv` reverses the order of the cycles as well.
`palindrome` is the pattern, then `rev` of it, one per cycle: on a one-bar source such as
`n("0 2 4 7")`, that is up, then down, forever.
</Box>

## jux — one ear at a time

`jux(f)` plays the pattern hard left and `f(pattern)` hard right. Use headphones for this one.

<Exercise id="pattern-functions/jux" title="Split the stereo image"
  goal="Hear `jux` as what it really is: two lanes, panned hard, one of them transformed."
  start={`n("0 1 [4 3] 2 0 2 [~ 3] 4").s("jazz")`}
  target={`n("0 1 [4 3] 2 0 2 [~ 3] 4").s("jazz").jux(x => x.speed(1.5))`}>
  <Step check={{ includes: '.jux(rev)', match: { keys: ['n', 'pan'] } }}
        target={`n("0 1 [4 3] 2 0 2 [~ 3] 4").s("jazz").jux(rev)`}
        hints={['`rev` goes in bare, with no parentheses — you are handing `jux` the function itself.']}
        solution={`n("0 1 [4 3] 2 0 2 [~ 3] 4").s("jazz").jux(rev)`}>
    Add `.jux(rev)`. The left ear plays the phrase, the right ear plays it backwards, and the two
    cross in the middle of the bar.
  </Step>
  <Step check={{ includes: '.pan(1)', excludes: '.jux(', match: { keys: ['n', 'pan'] } }}
        target={`n("0 1 [4 3] 2 0 2 [~ 3] 4").s("jazz").jux(rev)`}
        hints={['Two `$:` lanes, the same `n(...)` in both.', 'One gets `.pan(0)`, the other `.pan(1)` and `.rev()`.']}
        solution={`$: n("0 1 [4 3] 2 0 2 [~ 3] 4").s("jazz").pan(0)
$: n("0 1 [4 3] 2 0 2 [~ 3] 4").s("jazz").pan(1).rev()`}>
    Write out what that shorthand stands for: two `$:` lanes of the same pattern, one `.pan(0)`,
    one `.pan(1).rev()`. It should sound exactly the same.
  </Step>
  <Step check={{ includes: '.juxBy(', fn: "(h) => { const p = [...new Set(h.map(e => e.value.pan))].sort(); return (h.length === 18 && p.length === 2 && p[0] > 0 && p[1] < 1) || 'Expected both copies still there, but panned somewhere between hard left and hard right.' }" }}
        hints={['Back to one line, and the amount is the first argument.']}
        solution={`n("0 1 [4 3] 2 0 2 [~ 3] 4").s("jazz").juxBy(.5, rev)`}>
    Go back to one line and narrow the split: `.juxBy(.5, rev)`. The two copies move towards the
    centre — `0` would be mono, `1` is the full `jux`.
  </Step>
  <Step check={{ includes: '.jux(', excludes: '.juxBy(', match: { keys: ['n', 'pan', 'speed'] } }}
        hints={['An inline arrow function, like the ones you pass to `map`.']}
        solution={`n("0 1 [4 3] 2 0 2 [~ 3] 4").s("jazz").jux(x => x.speed(1.5))`}>
    `jux` takes *any* function, not just `rev`. Widen it back out and change the transform:
    `.jux(x => x.speed(1.5))`. Same notes both sides, but the right ear is sped up.
  </Step>
</Exercise>

<Box kind="try">
Try `jux(x => x.add(note(7)))`, `jux(x => x.fast(1.5))`, `jux(x => x.lpf(400))`. Anything you can
do to a pattern you can do to only one ear.
</Box>

## off — copy, delay, modify

`off(time, f)` superimposes a modified copy, shifted by `time` cycles. It is a delay line where
you choose what happens to the echo.

<Exercise id="pattern-functions/off" title="Build a texture out of one line"
  goal="Turn three notes into nine by stacking shifted, transposed, quieter copies."
  start={`note("c3 eb3 g3").s("triangle").decay(.15).sustain(0)`}
  target={`note("c3 eb3 g3").s("triangle").decay(.15).sustain(0)
  .off(3/16, x => x.add(note(7)).gain(.4)
    .off(1/8, y => y.add(note(5)).gain(.2)))`}>
  <Step check={{ includes: '.off(', match: { keys: ['note'] } }}
        target={`note("c3 eb3 g3").s("triangle").decay(.15).sustain(0)
  .off(1/8, x => x.add(note(7)))`}
        hints={['`1/8` is an eighth of a cycle, so the copy lands an eighth note later.']}
        solution={`note("c3 eb3 g3").s("triangle").decay(.15).sustain(0)
  .off(1/8, x => x.add(note(7)))`}>
    Add `.off(1/8, x => x.add(note(7)))` on a new line. Six notes now: the original three, plus
    three a fifth up, an eighth of a cycle later.
  </Step>
  <Step check={{ includes: '.gain(', fn: "(h) => { const q = h.filter(e => e.value.gain === 0.4).length; return (h.length === 6 && q === 3) || 'Expected 6 notes, the 3 copies at gain .4 and the originals untouched.' }" }}
        hints={['Chain it inside the arrow function, after the `add`.']}
        solution={`note("c3 eb3 g3").s("triangle").decay(.15).sustain(0)
  .off(1/8, x => x.add(note(7)).gain(.4))`}>
    The copy is as loud as the original, which is not what an echo does. Add `.gain(.4)` to the
    transform: `x => x.add(note(7)).gain(.4)`.
  </Step>
  <Step check={{ events: 9, includes: '.gain(.2' }}
        hints={['The second `off` chains onto `x`, inside the first arrow function.', 'Name the inner argument something else, `y`, so you can see which is which.']}
        solution={`note("c3 eb3 g3").s("triangle").decay(.15).sustain(0)
  .off(1/8, x => x.add(note(7)).gain(.4)
    .off(1/8, y => y.add(note(5)).gain(.2)))`}>
    `off` can go inside `off`. Give the copy its own copy:
    `.off(1/8, y => y.add(note(5)).gain(.2))`, chained onto `x`. Nine notes from three.
  </Step>
  <Step check={{ includes: '3/16', match: { keys: ['note', 'gain'] } }}
        hints={['Only the outer one — leave the inner `1/8` alone.', 'A dotted eighth is 3/16 of a bar.']}
        solution={`note("c3 eb3 g3").s("triangle").decay(.15).sustain(0)
  .off(3/16, x => x.add(note(7)).gain(.4)
    .off(1/8, y => y.add(note(5)).gain(.2)))`}>
    Move the outer copy to a dotted eighth: change the **outer** `1/8` to `3/16`. The whole thing
    starts to limp, in a good way.
  </Step>
</Exercise>

<Box kind="warn">
`.add(7)` inside an `off` does nothing if the pattern has already been through `note()` or `n()`:
you get a *"Can't do arithmetic on control pattern"* warning in the console and silence where the
transposition should be. Either wrap the number in the same control — `.add(note(7))` — or do the
arithmetic before you name the control: `"c3 eb3 g3".off(1/8, x => x.add(7)).note()`.
</Box>

## superimpose and layer

<Exercise id="pattern-functions/layer" title="From one part to two instruments"
  goal="Add a copy on top, then throw the original away and keep only the copies."
  start={`note("c3 eb3 g3 bb3").lpf(900).s("sawtooth")`}
  target={`note("c3 eb3 g3 bb3").lpf(900)
  .layer(x => x.s("sawtooth"), x => x.s("square").add(note(12)))`}>
  <Step check={{ includes: '.superimpose(', match: { keys: ['note', 's'] } }}
        target={`note("c3 eb3 g3 bb3").lpf(900).s("sawtooth").superimpose(x => x.add(note(12)))`}
        hints={['It takes only a function — no time argument.']}
        solution={`note("c3 eb3 g3 bb3").lpf(900).s("sawtooth").superimpose(x => x.add(note(12)))`}>
    Add `.superimpose(x => x.add(note(12)))`. Eight notes: the line, plus the same line an octave
    up, exactly on top.
  </Step>
  <Step check={{ includes: '.off(0', match: { keys: ['note', 's'] } }}
        target={`note("c3 eb3 g3 bb3").lpf(900).s("sawtooth").superimpose(x => x.add(note(12)))`}
        hints={['The same transform, with a time of zero.']}
        solution={`note("c3 eb3 g3 bb3").lpf(900).s("sawtooth").off(0, x => x.add(note(12)))`}>
    Replace `superimpose` with `.off(0, x => x.add(note(12)))`. Identical. `superimpose(f)` *is*
    `off(0, f)`.
  </Step>
  <Step check={{ includes: '.layer(', match: { keys: ['note'] } }}
        target={`note("c3 eb3 g3 bb3").lpf(900).s("sawtooth").layer(x => x.add(note(12)), x => x.add(note(7)))`}
        hints={['`layer` takes any number of functions, separated by commas.', 'Nothing in the list means "leave it alone", so the original is gone.']}
        solution={`note("c3 eb3 g3 bb3").lpf(900).s("sawtooth")
  .layer(x => x.add(note(12)), x => x.add(note(7)))`}>
    Replace it with `.layer(x => x.add(note(12)), x => x.add(note(7)))`. Still eight notes, but the
    untransposed original has vanished: `layer` keeps only what you list.
  </Step>
  <Step check={{ includes: '.s("square")', match: { keys: ['note', 's', 'lpf'] } }}
        hints={['Move the `.s("sawtooth")` out of the chain and into the first layer.']}
        solution={`note("c3 eb3 g3 bb3").lpf(900)
  .layer(x => x.s("sawtooth"), x => x.s("square").add(note(12)))`}>
    That is what `layer` is really for: two instruments from one source. Delete `.s("sawtooth")`
    from the chain and make the layers
    `x => x.s("sawtooth")` and `x => x.s("square").add(note(12))`.
  </Step>
</Exercise>

## Repeating events

<Exercise id="pattern-functions/ply" title="ply, echo, echoWith"
  goal="Three ways of turning one hit into several, and how they differ."
  start={`s("bd sd [~ bd] sd").bank("RolandTR707")`}
  target={`s("bd sd [~ bd] sd").bank("RolandTR707").echoWith(3, 1/6, (p, n) => p.speed(n + 1))`}>
  <Step check={{ includes: '.ply(', events: 8 }}
        hints={['It is the same as writing `*2` on every single element.']}
        solution={`s("bd sd [~ bd] sd").bank("RolandTR707").ply(2)`}>
    Add `.ply(2)`. Every event is now two events in the same slot — eight hits instead of four.
  </Step>
  <Step check={{ includes: 'ply("<', cycles: 3, events: 24 }}
        hints={['`< >` gives one value per cycle.']}
        solution={`s("bd sd [~ bd] sd").bank("RolandTR707").ply("<1 2 3>")`}>
    The argument is a pattern, which is where `ply` earns its place. Change it to `.ply("<1 2 3>")`:
    plain, doubled, tripled, one bar each.
  </Step>
  <Step check={{ includes: '.echo(', events: 12 }}
        hints={['`echo(times, timeOffset, feedback)` — three numbers.', 'Three repeats, a sixth of a cycle apart, each at 0.8 of the one before.']}
        solution={`s("bd sd [~ bd] sd").bank("RolandTR707").echo(3, 1/6, .8)`}>
    `ply` stacks the copies inside the slot. `echo` spreads them out in time and fades them.
    Replace it with `.echo(3, 1/6, .8)`.
  </Step>
  <Step check={{ includes: '.echoWith(', fn: "(h) => { const sp = [...new Set(h.map(e => e.value.speed))].sort((a, b) => a - b); return (h.length === 12 && sp.join(' ') === '1 2 3') || 'Expected 12 events with speeds 1, 2 and 3 — one speed per repeat.' }" }}
        hints={['The transform gets two arguments: the pattern, and which repeat it is (counting from 0).']}
        solution={`s("bd sd [~ bd] sd").bank("RolandTR707").echoWith(3, 1/6, (p, n) => p.speed(n + 1))`}>
    `echoWith(times, time, f)` hands you the repeat number, so each copy can differ. Replace the
    line with `.echoWith(3, 1/6, (p, n) => p.speed(n + 1))`: each repeat plays a step higher.
  </Step>
</Exercise>

<Box kind="warn">
`stut(times, feedback, time)` does the same job as `echo` with the **last two arguments swapped**.
`echo(3, 1/6, .8)` is `stut(3, .8, 1/6)`. If your repeats come out at the wrong spacing, that is
usually why.
</Box>

## Applying a function some of the time

| Function | Applies `f`… |
| --- | --- |
| `every(n, f)`, `firstOf(n, f)` | on the first of every n cycles |
| `lastOf(n, f)` | on the last of every n cycles |
| `when(binaryPattern, f)` | wherever the pattern is true |
| `within(start, end, f)` | only to a part of each cycle |

<Exercise id="pattern-functions/conditional" title="A fill, four ways"
  goal="Put a double-time fill in the right bar, then in the right half of every bar."
  start={`s("bd sd bd sd, hh*8").bank("RolandTR909")`}
  target={`s("bd sd bd sd, hh*8").bank("RolandTR909").within(.5, 1, x => x.ply(2))`}>
  <Step check={{ includes: '.every(4', cycles: 4, match: { keys: ['s'] } }}
        target={`s("bd sd bd sd, hh*8").bank("RolandTR909").every(4, x => x.ply(2))`}
        hints={['The function you pass is the same kind of arrow function `jux` took.']}
        solution={`s("bd sd bd sd, hh*8").bank("RolandTR909").every(4, x => x.ply(2))`}>
    Add `.every(4, x => x.ply(2))` and count bars. The fill lands on bar **1** of every four, which
    is almost never where you want it.
  </Step>
  <Step check={{ includes: '.lastOf(', cycles: 4, match: { keys: ['s'] } }}
        target={`s("bd sd bd sd, hh*8").bank("RolandTR909").lastOf(4, x => x.ply(2))`}
        hints={['Only the function name changes.']}
        solution={`s("bd sd bd sd, hh*8").bank("RolandTR909").lastOf(4, x => x.ply(2))`}>
    Change `every` to `lastOf`. Bar 4 of every four: a fill going into the next phrase.
  </Step>
  <Step check={{ includes: '.when(', cycles: 4, match: { keys: ['s'] } }}
        target={`s("bd sd bd sd, hh*8").bank("RolandTR909").lastOf(4, x => x.ply(2))`}
        hints={['One value per cycle, three off and one on.', '`when` reads 0 as false and anything else as true.']}
        solution={`s("bd sd bd sd, hh*8").bank("RolandTR909").when("<0 0 0 1>", x => x.ply(2))`}>
    Now spell the same thing out by hand: `.when("<0 0 0 1>", x => x.ply(2))`. Identical to
    `lastOf(4, …)`, but the schedule is a pattern you can write anything into.
  </Step>
  <Step check={{ includes: '.within(', match: { keys: ['s'] } }}
        hints={['`within` takes two positions in the cycle, 0 to 1.', 'The second half runs from .5 to 1.']}
        solution={`s("bd sd bd sd, hh*8").bank("RolandTR909").within(.5, 1, x => x.ply(2))`}>
    Replace it with `.within(.5, 1, x => x.ply(2))`: not *some bars*, but the same half of **every**
    bar.
  </Step>
</Exercise>

<Box kind="warn">
`within` filters first and applies `f` second, so a function that moves events in time can throw
them outside the window you named. `within(0, .5, x => x.fast(2))` takes the first half's events
and then speeds them up across the whole cycle. Functions that stay put — `ply`, `speed`, `gain`,
`lpf` — behave the way you expect.
</Box>

## Applying a function some of the *time*

<Exercise id="pattern-functions/chance" title="Roll the dice"
  goal="Hit-by-hit randomness, then cycle-by-cycle randomness, then dropping hits altogether."
  start={`s("hh*8")
  .bank("RolandTR909")`}
  target={`s("hh*8")
  .bank("RolandTR909")
  .often(x => x.speed(2))
  .someCyclesBy(.5, x => x.gain(.4))
  .degradeBy(.3)`}>
  <Step check={{ includes: '.sometimesBy(', cycles: 8, fn: "(h) => { const n = h.filter(e => e.value.speed === 2).length; return (h.length === 64 && n > 14 && n < 50) || 'Expected all 64 hats, with roughly half of them at speed 2 (got ' + h.filter(e => e.value.speed === 2).length + ').' }" }}
        hints={['`sometimesBy(probability, f)` — the probability comes first.']}
        solution={`s("hh*8")
  .bank("RolandTR909")
  .sometimesBy(.5, x => x.speed(2))`}>
    Add `.sometimesBy(.5, x => x.speed(2))` on a new line. Every hat still plays; about half of them are pitched
    up. Let it run — the choice is remade every cycle.
  </Step>
  <Step check={{ includes: '.sometimes(', excludes: '.sometimesBy(', cycles: 8, fn: "(h) => { const n = h.filter(e => e.value.speed === 2).length; return (h.length === 64 && n > 14 && n < 50) || 'It should still sound like the previous step.' }" }}
        hints={['There is a named shortcut for exactly 0.5.']}
        solution={`s("hh*8")
  .bank("RolandTR909")
  .sometimes(x => x.speed(2))`}>
    Change `sometimesBy(.5,` to `sometimes(` — the named shortcut for 0.5. No audible change.
  </Step>
  <Step check={{ includes: '.often(', cycles: 8, fn: "(h) => { const n = h.filter(e => e.value.speed === 2).length; return (h.length === 64 && n > 34 && n < 62) || 'Expected roughly three quarters of the 64 hats at speed 2 (got ' + h.filter(e => e.value.speed === 2).length + ').' }" }}
        hints={['The next one up the list.']}
        solution={`s("hh*8")
  .bank("RolandTR909")
  .often(x => x.speed(2))`}>
    Change `sometimes` to `often`, which is 0.75. Noticeably more of them jump.
  </Step>
  <Step check={{ includes: '.someCyclesBy(', cycles: 8, fn: "(h) => { const byCycle = [0,1,2,3,4,5,6,7].map(c => h.filter(e => Math.floor(e.t) === c)); const loud = byCycle.filter(c => c.length && c.every(e => e.value.gain === 0.4)).length; const none = byCycle.filter(c => c.length && c.every(e => e.value.gain === undefined)).length; return (loud > 0 && none > 0 && loud + none === 8) || 'Expected whole bars at gain .4 and whole bars untouched — never a mix inside one bar.' }" }}
        hints={['`someCyclesBy` has the same shape as `sometimesBy`.', 'A new line after the `often(...)`.']}
        solution={`s("hh*8")
  .bank("RolandTR909")
  .often(x => x.speed(2))
  .someCyclesBy(.5, x => x.gain(.4))`}>
    Add `.someCyclesBy(.5, x => x.gain(.4))`. Listen to the difference: this decides once per bar,
    so a whole bar is quiet or a whole bar is not. `sometimesBy` decides per hit.
  </Step>
  <Step check={{ includes: '.degradeBy(', cycles: 8, events: [30, 58] }}
        hints={['`degradeBy(p)` drops each event with probability p.']}
        solution={`s("hh*8")
  .bank("RolandTR909")
  .often(x => x.speed(2))
  .someCyclesBy(.5, x => x.gain(.4))
  .degradeBy(.3)`}>
    Finally, stop playing some of them: add `.degradeBy(.3)`. Three hats in ten go missing.
    (`degrade` is `degradeBy(.5)`.)
  </Step>
</Exercise>

| Name | Probability |
| --- | --- |
| `never` | 0 |
| `almostNever` | 0.1 |
| `rarely` | 0.25 |
| `sometimes` | 0.5 |
| `often` | 0.75 |
| `almostAlways` | 0.9 |
| `always` | 1 |

Each is `sometimesBy` with that number baked in, and each has a `someCycles…` twin
(`rarelyCycles`, and so on) that decides per cycle instead of per event.

## Reordering

<Exercise id="pattern-functions/reorder" title="Shuffle the deck"
  goal="Four ways of playing the same four notes in a different order each cycle."
  start={`n("0 1 2 3").scale("A:minor").s("piano")`}
  target={`n("0 1 2 3").scale("A:minor").s("piano").chunk(4, x => x.add(note(7)))`}>
  <Step check={{ includes: '.iter(', cycles: 4, match: { keys: ['note'] } }}
        target={`n("0 1 2 3").scale("A:minor").s("piano").iter(4)`}
        hints={['`iter(n)` cuts the cycle into n parts and starts one part later each cycle.']}
        solution={`n("0 1 2 3").scale("A:minor").s("piano").iter(4)`}>
    Add `.iter(4)`. Bar 1 starts on note 0, bar 2 on note 1, bar 3 on note 2 — the phrase rotates.
  </Step>
  <Step check={{ includes: '.shuffle(', cycles: 4, events: 16, fn: "(h) => [0,1,2,3].every(c => new Set(h.filter(e => Math.floor(e.t) === c).map(e => e.value.note)).size === 4) || 'Expected all four notes exactly once in every bar.'" }}
        hints={['Same argument, different name.']}
        solution={`n("0 1 2 3").scale("A:minor").s("piano").shuffle(4)`}>
    Change `iter` to `shuffle`. Still four parts, still all four in every bar — but in a random
    order, like dealing a shuffled deck.
  </Step>
  <Step check={{ includes: '.scramble(', cycles: 4, events: 16 }}
        hints={['One more name for the same argument.']}
        solution={`n("0 1 2 3").scale("A:minor").s("piano").scramble(4)`}>
    Change `shuffle` to `scramble`. It picks each slot independently, so parts repeat and others
    never show up. Let it run a while and you will hear notes land twice in a row.
  </Step>
  <Step check={{ includes: '.add(', excludes: 'scramble', cycles: 4, match: { keys: ['note'] } }}
        target={`n("0 1 2 3").scale("A:minor").s("piano").add(note(7))`}
        hints={['`add(note(7))` adds 7 semitones to every note.']}
        solution={`n("0 1 2 3").scale("A:minor").s("piano").add(note(7))`}>
    Replace `.scramble(4)` with `.add(note(7))`. Back in order, and every note is now 7 semitones
    higher: the whole riff moved up.
  </Step>
  <Step check={{ includes: '.chunk(', cycles: 4, match: { keys: ['note'] } }}
        hints={['`chunk(n, f)` applies `f` to a different nth of the cycle each cycle.', 'The transposition becomes the `f`: `x => x.add(note(7))`.']}
        solution={`n("0 1 2 3").scale("A:minor").s("piano").chunk(4, x => x.add(note(7)))`}>
    Wrap it so it only hits part of the bar: `.chunk(4, x => x.add(note(7)))`. Nothing is
    reordered; instead a different quarter of the bar is transposed each time round.
  </Step>
</Exercise>

## Taking the rhythm from somewhere else

<Exercise id="pattern-functions/struct" title="struct, mask, beat"
  goal="Give a one-note-per-bar pattern a rhythm three different ways, and hear which one creates events."
  start={`note("<c3 eb3 g3>")
  .s("sawtooth")
  .lpf(800)`}
  target={`note("<c3 eb3 g3>")
  .s("sawtooth")
  .lpf(800)
  .beat("0,4,6,10,14", 16)`}>
  <Step check={{ includes: '.struct(', events: 5 }}
        hints={['`x` means on, `~` means off, and there are eight slots.']}
        solution={`note("<c3 eb3 g3>")
  .s("sawtooth")
  .lpf(800)
  .struct("x ~ x x ~ x ~ x")`}>
    One long note per bar. Add `.struct("x ~ x x ~ x ~ x")`: five hits, all on the same note.
    The rhythm came from the **right**, the pitch from the left.
  </Step>
  <Step check={{ includes: '.mask(', events: 1 }}
        hints={['Only the function name changes.', '`mask` cannot create events — it can only remove ones that exist.']}
        solution={`note("<c3 eb3 g3>")
  .s("sawtooth")
  .lpf(800)
  .mask("x ~ x x ~ x ~ x")`}>
    Change `struct` to `mask` and count: one event. There was only ever one note in the bar, and
    `mask` filters what is there instead of creating anything.
  </Step>
  <Step check={{ includes: '.beat(', match: { keys: ['note'] } }}
        target={`note("<c3 eb3 g3>")
  .s("sawtooth")
  .lpf(800)
  .struct("x ~ x x ~ x ~ x")`}
        hints={['Eight slots out of a bar is the same as sixteen steps, counting the on ones.', '`beat(positions, steps)` counts from 0.']}
        solution={`note("<c3 eb3 g3>")
  .s("sawtooth")
  .lpf(800)
  .beat("0,4,6,10,14", 16)`}>
    Same rhythm, written as step numbers instead of a grid: replace the `.mask(...)` line with
    `.beat("0,4,6,10,14", 16)`. It should sound exactly like the `struct` version.
  </Step>
</Exercise>

Grids get a whole chapter of their own — see <L to="/tutorial/time">Writing in Time</L> for
`struct`, `mask`, `beat`, `binaryN` and how to think on a step sequencer.

<QA q="When does the argument pattern add events, and when does it not?">
By default, structure comes from the **left** of the chain: `s("bd*4").speed("1 2")` is four kicks.
`struct` is the clean exception: it takes structure from the right. `squeeze` takes it from both
sides. `ply` looks like it adds events from the right, but it does not — it subdivides each event
the left pattern already had. `stack` / `,` combines everything. If you are surprised by how many
events you get, ask which side the structure came from.
</QA>

<Box>
`inside(n, f)` is `f(pattern.slow(n)).fast(n)` and `outside(n, f)` is `f(pattern.fast(n)).slow(n)`
— so `outside(n, f)` is just `inside(1/n, f)`. Reach for them when a function like `rev`, `shuffle`
or `iter` is operating on the wrong unit of time.
</Box>

## Choosing between whole patterns

`squeeze(index, list)` takes a list of patterns (a real JavaScript array) and an index pattern that
says which one to play. The editor starts on index `"0"`: the first phrase, `g3 a3`, every bar.

<Exercise id="pattern-functions/pick" title="squeeze and pick"
  goal="Select a sub-pattern with a number, and hear what changes when it is not squeezed to fit."
  start={`note(squeeze("0", ["g3 a3", "f3 g3 f3 g3"])).s("gm_electric_guitar_muted")`}
  target={`note(pick("0 1", ["g3 a3", "f3 g3 f3 g3"])).s("gm_electric_guitar_muted")`}>
  <Step check={{ includes: '<0 1>', cycles: 2, match: { keys: ['note'] } }}

        hints={['Only the first argument changes.', '`< >` gives one value per bar.']}
        solution={`note(squeeze("<0 1>", ["g3 a3", "f3 g3 f3 g3"])).s("gm_electric_guitar_muted")`}>
    Change the index pattern from `"0"` to `"<0 1>"`. Bar 1 plays the first phrase, bar 2 the
    second.
  </Step>
  <Step check={{ includes: 'squeeze("0 1"', match: { keys: ['note'] } }}
        target={`note(squeeze("0 1", ["g3 a3", "f3 g3 f3 g3"])).s("gm_electric_guitar_muted")`}
        hints={['A space instead of the angle brackets makes it two events in one bar.']}
        solution={`note(squeeze("0 1", ["g3 a3", "f3 g3 f3 g3"])).s("gm_electric_guitar_muted")`}>

  </Step>
  <Step check={{ includes: 'pick(', excludes: 'squeeze', match: { keys: ['note'] } }}

        solution={`note(pick("0 1", ["g3 a3", "f3 g3 f3 g3"])).s("gm_electric_guitar_muted")`}>
    Change `squeeze` to `pick`. Four notes now, not six: `pick` does not compress the chosen
    pattern into the slot — it lets it run at its own speed and you hear the window that fits.
  </Step>
</Exercise>

`pickF` does the same for **functions** instead of patterns.
`s("bd*4").pickF("<0 1>", [x => x.fast(2), x => x.rev()])` alternates between doubling and
reversing, one bar each.

## The rest of the family

These come up less often, but they are worth recognising. The
<L to="/reference/cheatsheet">cheat sheet</L> has them all in one place.

| Function | What it does |
| --- | --- |
| `firstOf(n, f)` | the same as `every(n, f)`, named the other way round |
| `stut(times, feedback, time)` | `echo` with the last two arguments swapped |
| `degrade` | `degradeBy(.5)` |
| `undegradeBy(p)` | keeps exactly what `degradeBy(p)` would have dropped |
| `iterBack(n)` | `iter`, rotating the other way |
| `outside(n, f)` | `inside(1/n, f)` |
| `pickF(pat, fs)` | chooses a function from a list, instead of a pattern |
| `binaryN(n, bits)` | a `struct` grid written as a number |

For building a whole arrangement out of these — masks that come in every 8 bars, fills in the last
bar of a phrase, `arrange` for sections — see the long-form part of
<L to="/tutorial/time">Writing in Time</L>.

## Recap

| Function | Purpose |
| --- | --- |
| `rev` `revv` `palindrome` | reverse, within a cycle or across cycles |
| `jux` `juxBy` | split stereo, modify one side |
| `off` `superimpose` `layer` | add modified copies |
| `ply` `echo` `echoWith` | repeat events |
| `every` `firstOf` `lastOf` `when` `within` | conditional application |
| `sometimesBy` `someCyclesBy` + named shortcuts | probabilistic application |
| `degradeBy` `undegradeBy` | drop events, and keep the complement |
| `shuffle` `scramble` `iter` `chunk` | reorder |
| `struct` `mask` `beat` | impose or filter rhythm |
| `zoom` `linger` `inside` `outside` | change the time window |
| `squeeze` `pick` `pickF` | choose between patterns or functions |
