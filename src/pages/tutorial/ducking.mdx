In a DAW you put a compressor on the bass and feed the kick into its sidechain input. Strudel skips
the compressor entirely: **a pattern directly ducks an orbit.** The kick says "whenever I hit, turn
orbit 2 down", and that is the whole mechanism.

<Box>
The thing you duck is a **bus**, not a pattern, so <L to="/tutorial/orbits">Orbits</L> is a
prerequisite. If a sound is not on its own orbit, you cannot duck it on its own.
</Box>

Note what that ducking lane is: a normal, audible kick doing two jobs at once. You hear it, *and*
it ducks.

## The four controls

| Control | Aliases | Range | Meaning |
| --- | --- | --- | --- |
| `duckorbit` | `duck` | orbit number(s) | which orbit(s) to duck |
| `duckdepth` | — | 0…1 | how far down it goes (non-linear, see below) |
| `duckonset` | `duckons` | seconds | time to **reach** the lowest volume |
| `duckattack` | `duckatt` | seconds | time to **return** to normal volume |

<Box kind="warn">
The names are counter-intuitive if you come from compressors. `duckonset` is the *downward* ramp
(what a compressor calls attack) and `duckattack` is the *recovery* (what a compressor calls
release). Read them as: onset = going down, attack = coming back.
</Box>

The scale is not linear. Internally the orbit's gain drops to `1 - √depth`, floored at `0.01`:

| `duckdepth` | gain | roughly |
| --- | --- | --- |
| `0.1` | 0.68 | −3 dB |
| `0.3` | 0.45 | −7 dB |
| `0.5` | 0.29 | −11 dB |
| `0.6` | 0.22 | −13 dB |
| `1` | 0.01 | −40 dB |

So the first half of the knob does most of the audible work, and depth 1 is a very deep duck rather
than true silence. A duck can only ever lower the level, never raise it.

## duckonset: the ramp down, and the click

<Exercise id="ducking/onset" title="Kill the click, then abuse it"
  goal="Silence the ducker, hear the click at onset 0, remove it, then stretch the onset into a rhythm."
  start={`$: freq("63.2388").s("sine").orbit(2).gain(4)

$: s("bd*4").duckorbit(2).duckattack(0.3)`}
  target={`$: freq("63.2388").s("sine").orbit(2).gain(4)

$: s("bd*4").duckorbit(2).duckattack(0.05).duckonset(0.25).postgain(0)`}>
  <Step check={{ fn: "(h) => { const k = h.filter(e => e.value.s === 'bd'); return (k.length > 0 && k.every(e => e.value.postgain === 0)) || 'Add `.postgain(0)` to the kick lane.'; }" }}
        hints={['`postgain` is the level at the very end of the local chain — it silences the sound without removing the event.']}
        solution={`$: freq("63.2388").s("sine").orbit(2).gain(4)

$: s("bd*4").duckorbit(2).duckattack(0.3).postgain(0)`}>
    Add `.postgain(0)` to the kick lane. The kick vanishes but the ducking carries on: a pure
    sidechain trigger, and now you hear nothing but a steady tone being pushed down four times a bar.
  </Step>
  <Step check={{ fn: "(h) => { const k = h.filter(e => e.value.s === 'bd'); return (k.length > 0 && k.every(e => e.value.duckonset === 0)) || 'Add `.duckonset(0)` to the kick lane.'; }" }}
        solution={`$: freq("63.2388").s("sine").orbit(2).gain(4)

$: s("bd*4").duckorbit(2).duckattack(0.3).duckonset(0).postgain(0)`}>
    Add `.duckonset(0)`. Listen at the start of each duck: an instantaneous volume jump is a step
    in the waveform, and a step in the waveform is a click.
  </Step>
  <Step check={{ fn: "(h) => { const k = h.filter(e => e.value.s === 'bd'); return (k.length > 0 && k.every(e => e.value.duckonset >= 0.005 && e.value.duckonset <= 0.02)) || 'Change it to `.duckonset(0.01)`.'; }" }}
        solution={`$: freq("63.2388").s("sine").orbit(2).gain(4)

$: s("bd*4").duckorbit(2).duckattack(0.3).duckonset(0.01).postgain(0)`}>
    Change it to `.duckonset(0.01)`. Ten milliseconds — too short to hear as a ramp, long enough
    for the click to disappear completely. This is the safe default.
  </Step>
  <Step check={{ fn: "(h) => { const k = h.filter(e => e.value.s === 'bd'); return (k.length > 0 && k.every(e => e.value.duckonset >= 0.2 && e.value.duckonset <= 0.3)) || 'Change it to `.duckonset(0.25)`.'; }" }}
        hints={['A long onset is not a mistake to avoid: it is a shape, and the shape is musical.']}
        solution={`$: freq("63.2388").s("sine").orbit(2).gain(4)

$: s("bd*4").duckorbit(2).duckattack(0.3).duckonset(0.25).postgain(0)`}>
    Now go the other way: `.duckonset(0.25)`. The tone slides down over a quarter of a second
    instead of dropping. It stops sounding like a sidechain and starts sounding like a swell.
  </Step>
  <Step check={{ fn: "(h) => { const k = h.filter(e => e.value.s === 'bd'); return (k.length > 0 && k.every(e => e.value.duckonset >= 0.2 && e.value.duckattack <= 0.08)) || 'Keep the long onset and shorten `.duckattack` to 0.05.'; }" }}
        solution={`$: freq("63.2388").s("sine").orbit(2).gain(4)

$: s("bd*4").duckorbit(2).duckattack(0.05).duckonset(0.25).postgain(0)`}>
    Keep the long onset and change `.duckattack(0.3)` to `.duckattack(0.05)`. The envelope is now
    reversed: a slow fall and an instant jump back. Proof that the two controls are independent,
    and a good reminder of which is which.
  </Step>
</Exercise>

<Box>
Rule: `duckonset(0.01)` or thereabouts is the safe default. Set it to 0 only when you want the
click as a percussive artefact.
</Box>

## Ducking several orbits at once

`duckorbit` takes a colon-separated list, and every other duck control can then take a matching
list — one value per orbit, in the same order.

## Ducking moves during a note

Ducking is one of the few things that genuinely varies **while** a note is sounding — along with
the ADSR envelopes, `tremolo`, `phaser`, `vib`, and anything driven by `lfo()` or `env()`. A
pattern-level `gain` cannot do this, and the difference is easiest to hear on a long held note.

<Exercise id="ducking/held-note" title="A fader cannot do this"

    a bar trying to get through it.
  </Step>
  <Step check={{ fn: "(h) => { const k = h.filter(e => e.value.s === 'supersaw'); return (k.length > 0 && k.every(e => e.value.gain === 0.4)) || 'Add `.gain(.4)` to the pad lane.'; }" }}

## Recipe: a rhythm made of absence

The ducker does not have to be a kick, or on the downbeat. Once it is silent, the only thing left
of it is the holes it makes.

<QA q="duckorbit, tremolo, or an lfo on gain — which gate should I use?">
`duckorbit` when the gate should follow a **rhythm**, and especially when the trigger is a real
sound in the mix — it is the only one that is genuinely rhythmic and that acts on a whole bus.
`tremolo` when you want a smooth, continuous wobble on one voice. `lfo({c:'gain', dc:-1})` when you
need an unusual shape, skew or curve. For sidechain, always `duckorbit`.
</QA>

<QA q="Can a pattern duck its own orbit?">
Yes, and it will duck itself — usually not what you want. Keep the ducker on a different orbit from
its target.
</QA>

<QA q="My per-orbit list is being ignored.">
Check that `duckorbit` itself is a list. `duckdepth("1:0.5")` only means anything next to something
like `duckorbit("2:3")`; with a single orbit there is nothing for the second value to apply to.
</QA>

## Recap

| Control | Purpose |
| --- | --- |
| `duckorbit(n)` / `duck` | which orbit(s) this pattern ducks |
| `duckorbit("2:3")` | duck several orbits |
| `duckdepth(0…1)` | how far down — gain becomes `1 − √depth`, floored at 0.01 |
| `duckonset(s)` | time to go down; ~0.01 avoids clicks |
| `duckattack(s)` | time to come back — this sets the feel |
| `"a:b"` on any of them | per-orbit values, in the same order |
| `postgain(0)` | make the ducker silent but still ducking |
